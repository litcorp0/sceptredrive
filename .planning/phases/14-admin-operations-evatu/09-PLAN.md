# Plan 09 — A report you can hand to an accountant

## Goal

The stock, credit ageing, payables ageing and loyalty liability screens each export the
rows the viewer may see and print a page that says what it is: period, branch, as-of,
generated when, by whom. The audit screen exports the trail without the payloads. No new
module, no second table, no figure computed in the browser.

## Tasks

### 1. One export button

Move `analytics/components/export-button.tsx` to `components/common/export-button.tsx`
(`GLOBAL_COMPONENTS` already allows `common` imports from any module), generalised to
`{ path, query, label?, disabled? }` and still using `apiDownload`. Update the five
analytics tabs to import it from `common` and delete the analytics copy — one implementation
or the next one drifts.

A `PrintButton` sits beside it: `window.print()` plus `aria-label` and a `disabled` state
while the query is fetching, because printing a skeleton is how a report gets a blank page
filed.

### 2. A print sheet and its provenance

`components/common/print-sheet.tsx`:

```tsx
<PrintSheet title="Stock report" meta={[
  { label: 'Branch', value: 'Accra Central (ACC)' },
  { label: 'Period', value: '1–31 Oct 2026' },
  { label: 'As at', value: '27 Oct 2026, 15:04' },
  { label: 'Generated by', value: 'Ama Mensah (GA-0002)' },
]}>
  {children}
</PrintSheet>
```

`hidden print:block` on the wrapper, `hidden` on the interactive toolbar while printing,
`@page` A4 already in `styles.css`. The meta block is not decoration: a printed page with
no period and no as-of is a page somebody will mis-file.

### 3. The stock report screen

`inventory/pages/stock-page.tsx` gains a report mode rather than a new route:

- filters: branch (admin), category, low-stock, and a **period** for the movement section;
- a totals bar above the table: products, units, value at average cost — from
  `totals`, never summed in the browser;
- below the table, three small sections from the report payload: movement flow by type,
  transfers dispatched/received/short-closed, counts completed with accuracy;
- Export and Print;
- the row cap: when `truncated` is true, a banner says the export contains the same 5 000
  rows and the filter must be narrowed.

The existing paged stock list stays for browsing; the report mode is one toggle
(`?report=true`) in the module's search schema.

### 4. The three existing report screens

- **Credit ageing** — Export + Print; the print sheet already exists as a heading, it moves
  into `PrintSheet`; the as-of date is the report's `asOf`, not today.
- **Payables ageing** — Export + Print; add the `print:` wrapper and a `PrintSheet` with the
  as-of and the supplier filter.
- **Loyalty** — Export + Print; **pass `branchId`** (the query type supports it and the page
  ignores it today), and print `asOf` with the liability, since the figure is as-of-now
  (P14-D21).
- **Audit** — Export; add the two filters the API already supports and the page does not
  expose (`actorId`, `entityId`); the table keeps showing before/after, the CSV never does,
  and a line under the export button says so.

Every table keeps rendering money through `formatGhs` from `admin/src/lib/format.ts`; the
CSV carries minor units and says so in its header (Plan 05).

### 5. Walkthrough

`admin/test/walkthrough-sections.mjs`: one assertion per screen that the export button
exists with the right `href`-equivalent and that the print sheet is in the DOM (hidden) with
a non-empty meta block. A second assertion that the loyalty print meta contains an as-of
timestamp. Downloads are not driven in the browser walkthrough — the CSV itself is proven
by the API tests — but the click must not produce a console error.
